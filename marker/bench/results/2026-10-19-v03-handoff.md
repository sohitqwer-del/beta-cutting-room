# Quality v0.3 handoff

The code is implemented and tested. None of the five measured search variants
beat its paired baseline, so **the existing 80/20 search default stays**. The
300-task and matched-time confirmations were deferred by the lead. **We cannot
claim that v0.3 beats Lectra at matched time, or is within one point at 60 seconds.**

The lead shortened the remaining work on 19 October: finish the current paired
development study, test and commit the code, and run only Simon, Teagan and Titan
at 60 seconds. No longer measurement was started after that instruction.

## Implementation

- Nesting uses `rules::flip_allowed` per piece. The native adapter generalizes
  the existing handedness-allocation approach per physical copy; constrained
  packing tries both permitted hands. Optional permissions are no longer a
  fabric-wide switch. Allocation changes between restart variants; Sparrow's
  source is unchanged.
- Tilt samples come from each piece's allowed rotations. The converter retains
  separate piece tilts and optional reflection, including the reflected phase.
  [Conversion audit](2026-10-19-v03-conversion.md): Tier A grows from 94,239 to
  95,661 tasks. Optional-mirror drops fall to zero. The remaining 1,086 tasks
  restrict angles or tilt. These are representation counts, not quality gains.
- Nest and match use canonical `rules::bundle_sizes` and physical cut outlines.
  The validator fix `55c0123` was merged as `2588c05` before the new-rule trials.
- Folded construction places fold halves first initially, then varies order.
  At each placement it compares an on-fold half with a full cut on two layers.
  Full cuts can produce surplus; warnings and demanded-product efficiency keep
  that surplus visible. This removes the previous forced-half policy on one
  fold edge. Its effect on Teagan efficiency has not been remeasured.
- Shade packing can put the shortest measured tail last when fixed/matching
  constraints permit it. An optional whole-bundle assignment search tests
  balanced, packed-first, ascending and mixed assignments. One attempt remains
  the default. Fixed transforms and optional-mirror copy identities are preserved.
- Search controls expose compression share, shrink/pool parameters, samplers,
  construction order, adaptive compression and full-worker sequential/race
  schedules with valid incumbents. The normal API and explicit tuning share the
  same path. Restart progress uses one clock and reports only improvements.

The search hypotheses follow the exploration/compression split in Gardeyn,
Vanden Berghe and Wauters, [arXiv:2509.13329v4](https://arxiv.org/html/2509.13329v4),
sections 7 and 9 and table 1. Only public parameters and the adapter were changed.

## Paired development results

Every arm attempted the same 40 frozen tasks, seed 1, with a 60-second search
budget. Two tasks ran concurrently with three separator workers each. Calls
were adjacent within each pair and alternated baseline-first/variant-first.
These are 40 tasks, not 400 independent samples.

Task 12127 cannot fit the converted strip at its only permitted angle: pieces
span 1286 and 1244 mm across a 1243 mm width. Its failure remains in every arm.
A frozen geometry proof, checked against the saved job before selection,
excludes it only from search selection. Each candidate needed all other 39
pairs to be valid. No task was replaced. All 195 eligible pairs were valid.

Differences are percentage points. Negative paired gain means lower mean variant
efficiency. Each variant has its own fresh baseline; rank paired gains, not raw
means from different periods.

The host was shared with other work and often at 100% CPU. Paired calls reduce
timing bias; they do not establish equal CPU time. Total CPU also saturates at
100%, so it cannot measure additional competition above that point. An
eight-minute sampling interruption affected two tasks. Both complete pairs were
replayed with the original executable; all four replayed layouts passed and no
persistent outlier remains. The audit flags high CPU or a telemetry gap over
30 seconds and never selects by score. Raw trials and replacement provenance
remain under `$BETA_DATA_DIR/marker-bench/quality-v03`.

An earlier unpaired baseline and interrupted/tooling attempts are retained but
excluded. [All experiments and exclusions](2026-10-19-v03-experiments.md).

## Exact quiet-machine commands for the lead

Run from `marker/` after setting the checkout's assigned external
`CARGO_TARGET_DIR` and `BETA_DATA_DIR`. Build first; run no build alongside timing.
Use fresh output directories. The wrappers sample CPU into conditions.json,
replay load/sampling outliers, and preserve raw evidence.

```powershell
$env:CARGO_BUILD_JOBS = '4'
cargo build --release -p beta-marker-cli --bin beta-marker
$exe = Join-Path $env:CARGO_TARGET_DIR 'release/beta-marker.exe'
$data = Join-Path $env:BETA_DATA_DIR 'marker-bench/quality-v03'
$profile = 'bench/experiments/v03/selected.json'
$common = @('--jobs','2','--threads-per-task','3','--seed','1','--search-config',$profile,'--runs','1')

./bench/tools/quality_study.ps1 -Executable $exe -MaxStartCpu 20 -Jobs 2 -Workers 3 -Output (Join-Path $data 'lectra-60s') -BenchmarkArguments (@('bench','lectra','--input',(Join-Path $data 'conversion/sample-300.jsonl'),'--time','60','--limit','300') + $common)

./bench/tools/quality_study.ps1 -Executable $exe -MaxStartCpu 20 -Jobs 2 -Workers 3 -Output (Join-Path $data 'lectra-match') -BenchmarkArguments (@('bench','lectra','--input',(Join-Path $data 'conversion/sample-match-60.jsonl'),'--time','match','--limit','60') + $common)
```

Matched time is not capped: it preserves 244–608 seconds, median 304. These are
search budgets; runtime and independent validation time are recorded separately.
The row label B denotes B-only; the all-task group (A plus B-only) is the
headline conservative Tier B comparison.
For the full originally requested suite, `quality_confirmation.ps1` accepts
`-Executable`, `-EvidenceRoot`, `-Jobs 2 -Workers 3 -MaxStartCpu 20`. It also runs
academic, garment, layout and shade checks. None was run at longer budgets here.

## Requests for the lead

1. Run quiet confirmation before a commercial-quality claim, then rerun the full
   workspace without snapshot skips after merging the UI fixes.
2. Check source task 12127 and the strip/angle interpretation with the dataset
   owner. Exact representation does not prove input feasibility.
3. Measure folded useful yield and shade loss before promoting those heuristics
   further. A full two-layer cut currently assigns both layers to one bundle.
   Consider `Placement.layer_bundles: Option<[Option<u32>; 2]>` for full layered
   cuts, with absent meaning legacy `bundle`, and separate validator demand
   accounting per layer. On-fold halves would retain their single-product rule.
   This would let two identical garments share one full cut without hiding surplus.
