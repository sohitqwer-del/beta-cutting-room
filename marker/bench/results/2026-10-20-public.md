# Public launch benchmark — 20 October 2026

**All 387 layouts passed independent validation.** The full public suite is complete. No trial was replaced or selected by its score. Raw jobs, layouts, CSVs, validator reports and load logs remain outside git.

At 60 seconds per task, BETA was **0.7296 percentage points behind Lectra on the mean**, with median **-1.2210 pp** and **84 wins / 12 ties / 204 losses** across 300 tasks. With Lectra’s recorded time per task, the mean was **slightly ahead, +0.4208 pp**, but the median was **-0.3044 pp** and BETA **won 25, tied 3 and lost 32 of 60**. This is an uneven, conditional sample result. It does not establish a general win over Lectra. Equal seconds do not imply equal compute.

## What was measured

The server used an AMD Ryzen 9 9900X3D: 12 physical cores, 24 logical CPUs, Linux 7.0.0-34 and Rust/Cargo 1.98.1. It was shared with other applications. Searches ran at nice 10, with four concurrent tasks and three search workers per task. This is a ceiling of 12 search workers, excluding coordinator/helper threads. The garment stages contain only three tasks, so their effective concurrency is three.

Engine revision: `a2d5de276e5d679acd00a023476ed84209924c57`, clean source. The baseline Cargo package version was 0.1.0; the launch product name is BETA Cutting Room. The final reproduction/export tool is pinned at `0ecfd71`. Its CPU nesting, matching, validator, runner and selected settings are identical to the server revision. Later UI/site merges do not change those CPU files. Original inherited compiler flags were not archived; the executable hash is in the evidence manifest.

The selected search is the existing 80% exploration / 20% compression profile, parallel portfolio, one run and seed 1. Academic trials use seeds 1, 2 and 3. FreeSewing uses seed 1 and the same default search settings. The learned predictor and experimental GPU paths are not called by this benchmark.

## Assumptions and scoring

**Sheet type 0 is assumed to mean an ordinary open, single-layer rectangular strip of the stated width.** No verified public codebook establishes that meaning. `flip_x=1` is assumed to reflect the x coordinate before rotation. Efficiency denominator and finite-sheet details in the source remain partly unverified. Correlation cannot prove those assumptions.

Tier A retains the exact allowed orientations under those assumptions. Tier B includes Tier A and retains a subset of source orientations. The v0.3 conversion preserves optional mirror choices and per-piece tilt. The 300-task sample contains 296 Tier A tasks and four Tier B-only tasks; the matched subset contains 59 and one. Unsupported constraint classes, codes 2/3 and unverified rings remain outside the headline. No sampled task has verified holes to correct.

The same task IDs and order as round 2 are frozen in `bench/public/*.ids.jsonl`. Sampling seed is 7030786. The 300 tasks balance 12 piece-count/reference-efficiency strata, 25 tasks each. The preselected matched subset has five per stratum. These are unweighted sample means, not population estimates.

Difference is BETA minus reference in percentage points. Ties are within 0.1 pp. Length saving is `100 × (1 - reference efficiency / BETA efficiency)`, averaged per task. Negative saving means a longer marker. Failed layouts would have no numeric score; `too_long` would count as an additional loss. No failures, pending-validator cases or `too_long` losses occurred. All 25 finite-length tasks at 60 seconds and all five matched-time finite-length tasks respected their limits.

## Comparison with round-2 laptop results

**The server-versus-laptop gain is confounded by hardware, engine, converter and load.** It is not an isolated hardware speedup. The laptop was an i9-11900H with 16 logical CPUs, five concurrent tasks and three workers each, with uncontrolled background work. Round 2 used revision `3022b1285ff7` with recorded local benchmark changes and the earlier converter. It fixed handedness and sometimes dropped mirror choices. The new conversion changes the exact-tier count from 293 to 296 in the 300-task sample.

A newer CPU, more physical cores and fewer concurrent search tasks can allow more work per search second. These are plausible contributors, not measured causal shares. Engine and conversion changes also matter. No controlled ablation separates them.

The server took longer in total wall time because it ran four concurrent tasks rather than five: 4414.466 versus 3599.976 seconds for the 300-task stage, and 4580.889 versus 3743.858 seconds for the matched stage. Queue throughput and per-task search quality are different measurements. Neither comparison is normalized to Lectra’s unknown hardware.

The website retains the completed laptop data under `lectra-60s-laptop-r2` and `lectra-matched-laptop-r2`. The new server results use `lectra-60s` and `lectra-matched`. Both hardware descriptions and dates remain visible.

## Reproduce on another machine

Use a fresh checkout at public runner commit `0ecfd71`. Set `BETA_DATA_DIR` and `CARGO_TARGET_DIR` to external directories, and `CARGO_BUILD_JOBS=3`. Prepare the pinned public inputs once using [the full protocol](../public/README.md). It covers downloads, checksum checks, the restricted pickle loader, exact task IDs and Windows/POSIX commands. About 9 GB of free RAM is needed for Lectra conversion.

Run from `marker/`:

```sh
cargo run --release --locked --manifest-path bench/public/Cargo.toml -- --out "$BETA_DATA_DIR/marker-bench/reproduction" --jobs 4 --workers 3
# 20 frozen tasks at 30 seconds each; pipeline check, not a launch score:
cargo run --release --locked --manifest-path bench/public/Cargo.toml -- --out "$BETA_DATA_DIR/marker-bench/smoke" --quick --jobs 2 --workers 3
# Export the same aggregate schema from saved evidence without new searches:
cargo run --release --locked --manifest-path bench/public/Cargo.toml -- --out "$BETA_DATA_DIR/marker-bench/reproduction" --summarize
```

On PowerShell use `$env:BETA_DATA_DIR` in the quoted paths. Choose fewer jobs/workers on smaller machines. The default resource allocation adapts to logical CPU count; an explicit oversized request is refused. Prefix the POSIX command with `nice -n 10` to use the recorded priority policy. `--time-scale` scales every budget, including matched durations; altered budgets receive smoke IDs and must not replace launch scores.

The command builds the CLI unless `--executable <path>` is supplied, then runs all five stages. The exact underlying server searches were:

```sh
EXE="$CARGO_TARGET_DIR/release/beta-marker"
INPUT="$BETA_DATA_DIR/marker-bench/public-inputs"
COMMON=(--jobs 4 --threads-per-task 3)
SEARCH=(--search-config bench/experiments/v03/selected.json --runs 1)
nice -n 10 "$EXE" bench lectra --input "$INPUT/sample-300.jsonl" --time 60 --limit 300 --seed 1 "${COMMON[@]}" "${SEARCH[@]}" --out "$OUT/lectra-60s"
nice -n 10 "$EXE" bench lectra --input "$INPUT/sample-match-60.jsonl" --time match --limit 60 --seed 1 "${COMMON[@]}" "${SEARCH[@]}" --out "$OUT/lectra-match"
nice -n 10 "$EXE" bench academic --time 60 --seeds 1,2,3 "${COMMON[@]}" "${SEARCH[@]}" --out "$OUT/academic-60s"
GARMENTS="testdata/open/freesewing/simon-ratio.job.json,testdata/open/freesewing/teagan-ratio.job.json,testdata/open/freesewing/titan-ratio.job.json"
for budget_seconds in 60 300; do
  nice -n 10 "$EXE" bench jobs --inputs "$GARMENTS" --time "$budget_seconds" --seed 1 "${COMMON[@]}" --out "$OUT/freesewing-${budget_seconds}s"
done
```

Set `OUT` to a fresh external output directory first. No input or runtime search downloads are needed after preparation. Fixed seeds do not make wall-clock searches bit-for-bit identical across machines, schedulers and builds. The same JSON schema and score definitions are reproduced; the measured values can differ.

## Validation, attribution and retained evidence

The final Rust tool passes five tests and Clippy with warnings denied. The real 20-task, 30-second smoke produced 20 valid layouts. A shortened 20-task pipeline smoke also completed with 20 valid layouts and valid exports. Neither smoke is published in the website data folder. The site’s 17 contract tests pass with the final data; its full build passes and checks for remote assets. Schema tests require full mean/median/outcome headlines, not a predetermined result sign.

The exporter verifies every scored CSV row against its saved successful independent validator report, checks task IDs/order and seeds, and retains failed-attempt counts. Original runner summaries agree with the exported aggregate means, medians and win/tie/loss counts. No new product dependency was added. The standalone tool uses permissive anyhow, clap, serde_json and sha2 dependencies, pinned in its lockfile.

Lectra attribution: Corentin Lallier, Laurent Vezard, Bruno Pinaud and Guillaume Blin (2022), *Nesting Tasks Dataset for 2D-Nesting Efficiency Estimation*, [Zenodo 7030786](https://doi.org/10.5281/zenodo.7030786), version 1.1, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Conversion changes units to mm, maps orientations and sometimes restricts them. The converter verifies the four pinned source MD5 values before restricted unpickling. Geometry is not included in git or the website JSON.

Academic source inputs are the MIT-licensed Sparrow v0.3.0 files, with URLs and SHA-256 values in [the input manifest](../public/inputs.json). Academic reference values come from the cited paper. FreeSewing fixture attribution and conversion details are in [the fixture README](../../testdata/open/freesewing/README.md).

Full evidence is retained under `$BETA_DATA_DIR/marker-bench/public-2026-10/`: `lectra-complete.tar.gz`, `extra-complete.tar.gz`, per-stage folders, raw summaries, inputs/settings hashes, machine information, both load logs, and independent validator reports.
