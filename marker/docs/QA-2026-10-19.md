## Findings

### QA-001 — Fixed: startup overwrites pending desktop recovery

Severity: high (loss of recovery data). Owner: desktop.

1. Install the existing 0.4.0 NSIS package into an isolated QA folder.
2. Open a `.betaproj` containing the public Simon job, named `QA recovery shirt`.
3. Wait for the five-second idle autosave, then kill only that app process.
4. Restart without a project argument. Leave **Recover autosave** untouched.
5. Inspect `recovery.json` and `recovery.beta-backup` after idle autosave.

Expected: both recovery records remain available until the operator chooses a
session. Actual: both files contained `Everyday shirt · demo`. The open session
could still recover its in-memory startup payload, but another restart would
lose that copy.

Fix: suspend autosave while a previous recovery is pending. **Recover autosave**
restores it. **Use current work instead** explicitly resumes autosave for the
current session. Regression tests cover repeated idle ticks and restarts,
explicit replacement, concurrent edits, busy operations and disk-write retry.
The fixed source was not launched a third time: the task's two-launch limit was
preserved. Installer testing used the original binary, not the patched source.

### QA-002 — Fixed: academic benchmark makes a runtime network request

Severity: medium (offline requirement). Owner: benchmark CLI.

Steps: run `beta-marker bench academic` with an allowed instance absent from
`BETA_DATA_DIR/datasets/esicup-sparrow`. Expected: a clear missing-local-data
error. Actual, established by source inspection: the loader spawned `curl` to
download from GitHub, with retries and a 180-second timeout. No download was
triggered during QA.

Fix: only read the local fixture. The error explains that data must be prepared
before benchmarking. Help no longer promises a download. A regression checks
that a missing fixture fails without creating a download directory. Existing
conversion tests retain coverage for valid cached geometry.

### QA-003 — Fixed: another pattern keeps stale grading geometry and reference

Severity: medium. Owner: Pattern UI.

1. Create/grade the rectangle through `runPatternSmoke()` and align on point `A`.
2. Load the teaching bodice, or open a Seamly shirt with different point IDs.
3. Open Grading, then edit a measurement and return to Grading.

Expected: outlines belong to the current document; absent reference points are
cleared. Actual: old overlays remained, and Grading could fail with
`nest reference point missing`. The bodice showed four old outlines instead of
its eight piece/size outlines.

Fix: clear a reference that is no longer a point and rebuild the grading cache
on refresh, with the existing generation check guarding asynchronous results.
`runPatternSwitchChecks()` is the browser regression: it drafts through real
forms, selects `A`, switches patterns, checks eight outlines and an empty stale
reference, then verifies an edited measurement redraws the grading.
The regression also retains a valid transformed point as the alignment
reference. Its final browser run passed all four assertions.
