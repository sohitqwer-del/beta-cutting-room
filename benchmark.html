Honest, repeatable results

Benchmark

We publish how BETA markers compare with a commercial engine’s recorded results and with published research. Every number comes with its method, its assumptions and the commands to repeat it.

In short

+0.42 ppMean vs Lectra with Lectra’s own time per task (60 tasks)median −0.30 pp · 25 wins, 3 ties, 32 losses
−0.73 ppMean vs Lectra at 60 seconds per task (300 tasks)median −1.22 pp · 84 wins, 12 ties, 204 losses
−1.51 ppvs the sparrow paper’s 20-minute means, with 60 seconds
360 / 360BETA layouts on Lectra tasks that passed the independent validator (300 at 60 s, 60 at Lectra’s time)

No general win over Lectra. With Lectra’s recorded time per task, BETA’s mean was +0.42 pp, but the median task was −0.30 pp, and BETA won 25, tied 3 and lost 32 of 60 tasks. With only 60 seconds per task, BETA’s mean was −0.73 pp (BETA won 84, tied 12 and lost 204 of 300 tasks). Equal seconds do not mean equal computing power: Lectra’s engine version and hardware are unknown, and these are sampled tasks, not all Lectra customers. At 60 seconds, small markers (up to 25 pieces) range from +0.05 to +4.62 pp across the efficiency groups. Markers with more than 75 pieces range from −3.70 to +0.07 pp. Large markers are where BETA needs the most work.

A percentage point (pp) is the difference between two efficiencies: 85% against 86% is 1 pp. At 85% efficiency, 1 pp is about 1.2% of marker length.

We have no matched tests against Tukatech, Gerber or Optitex. Their markers are not in any public dataset. Send us your markers and we will compare on your styles.

Lectra dataset: real client markers

The Lectra nesting dataset has 100,000 real nesting tasks from about 100 fashion customers. For each task it records the efficiency that Lectra’s own nesting engine reached. It is the only public source of commercial-engine results on real garment markers. We take a fixed, balanced sample, run BETA on the same pieces and fabric width, and compare.

One factory style (provisional, private)

On one real knitwear style from an Indian factory, BETA’s marker was 4.6% to 6.7% shorter than the marker from the factory’s Gemini CAD. This is one style. The data is private, so you cannot repeat the test, and it does not show that BETA beats Gemini in general. We need more factory comparisons: send us your markers.

Method

What we measure

  • Marker efficiency = total piece area ÷ (fabric width × marker length). Higher is better.
  • Difference = BETA efficiency minus the reference efficiency, in percentage points. A tie is within 0.1 points.
  • Length saving = 100 × (1 − reference efficiency ÷ BETA efficiency). Positive means BETA’s marker is shorter for the same pieces.
  • Means and medians use valid layouts only. A layout that is too long for a fixed sheet counts as a loss.

Every BETA marker is checked

An independent validator checks every BETA layout: all pieces present, no overlaps, grain and allowed rotations, fabric width and gaps. A layout that fails gets no score.

Fair rules: Tier A and Tier B

Each Lectra task says which rotations and mirror images each piece may use. Tier A tasks give BETA exactly the same choices. Tier B tasks give BETA the same choices or fewer, never more. The headline uses Tier B, which includes Tier A. Where BETA has fewer choices, that is a handicap for BETA, not for Lectra. Tasks with constraint types we cannot apply exactly are left out (3,253 of 100,000).

The sheet-type assumption

Each task has a sheet_type code. There is no public codebook. We assume code 0 means an ordinary open strip of fabric (one layer, the stated width). Code 0 covers 99,403 of 100,000 tasks. The strong correlation between BETA and Lectra results supports this, but does not prove it. Codes 2 and 3 are tested separately and never enter the headline.

Sample and time

The 300-task sample uses seed 7030786 and has 25 tasks in each of 12 groups (4 piece-count bands × 3 Lectra-efficiency bands). The 60-task subset for the matched-time run was chosen before any results were seen. Lectra’s engine version, hardware and number of workers are unknown, and its recorded times vary (244 to 608 seconds in our subset). Equal seconds do not mean equal computing power. Our machines were shared with other work.

What we do not claim

  • We do not claim BETA beats Lectra, Tukatech, Gerber, Optitex or any other commercial system.
  • The balanced sample describes those tasks. It is not an estimate for all Lectra customers.
  • Vendor fabric-saving claims (often 1–5%) are their own tests on their own data. Nobody has published a fair test between these tools.

Repeat the benchmark yourself

  1. Get the source code and install Rust. Python is needed once, to convert the Lectra dataset files.
  2. Choose a data folder outside the source code. Set BETA_DATA_DIR and CARGO_TARGET_DIR to folders on a disk with space.
  3. Convert the dataset. The converter checks the published checksums and reads the files with a restricted loader: 
    python -I bench/tools/lectra_convert.py download
python -I bench/tools/lectra_convert.py inspect
python -I bench/tools/lectra_convert.py self-test
python -I bench/tools/lectra_convert.py convert --sample-size 300 --seed 7030786
  4. Run the tests, then the benchmark commands shown under each result (“How to repeat this run”). Use a new output folder for each run. Reduce --jobs on a smaller computer.
  5. Each run writes run.json, results.csv and summary.md. The website reads summary files in the format described in marker/apps/site/data/benchmark/SCHEMA.md (external site).

Full instructions: marker/docs/benchmarks.md (external site). No pattern geometry is published on this site; the files contain totals and task IDs only.
