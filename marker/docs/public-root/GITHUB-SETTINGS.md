## Issue labels

| Labels | Use |
|---|---|
| `bug`, `enhancement`, `question`, `documentation` | Type of work |
| `good first issue`, `help wanted` | Bounded, ready-to-start tasks |
| `needs reproduction`, `needs review`, `blocked` | State |
| `pattern`, `marker`, `cutting-room`, `digitizing`, `export`, `install` | Area |
| `accessibility`, `translation`, `privacy`, `benchmark` | Cross-cutting topic |
| `priority: critical`, `priority: high`, `priority: normal` | Maintainer triage |

Public `privacy` labels are for sanitized issues only. Security vulnerabilities
belong in the private security route, not an issue template asking for secrets.

## Pinned issue: Send us one real order

**Suggested body:**

Help us test one complete job, from patterns to accepted cut pieces. Tell us
the workflow, fabric mode, quantities, devices and what you want to compare.
Start with a description only. Do not attach confidential patterns, factory or
buyer names, order records or photos of people. Contact sohitqwer@gmail.com to
agree permission and handling before any non-public evidence is shared.

Useful measures include operator time, fabric issued/returned, accepted garments,
overcut, surplus cut pieces and errors. A supervised trial is not proof of
general savings. We will agree which cleared summary, if any, may be published.

## Pinned issue: Good first issues

**Suggested body:**

New here? Pick a small task, leave a comment and read CONTRIBUTING.md. We need:

- One guide tested from a clean browser profile, using built-in samples.
- One Hindi/Tamil screen reviewed with a native-speaking cutter.
- One documentation link or unit-label fix with a clear before/after example.
- One synthetic DXF regression for a documented unsupported case.

Maintainers should split these into scoped issues with acceptance steps before
adding `good first issue`. Do not promise paid support or upload factory data.
