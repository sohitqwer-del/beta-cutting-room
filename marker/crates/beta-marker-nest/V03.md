# Version 0.3 nesting changes and experiment controls

`rules::flip_allowed` now resolves permissions per piece on both the Sparrow
allocation path and the obstacle/fold path. A true override can allow reflection
on faced fabric; a false override can forbid it on faceless fabric. The
Sparrow adapter still selects discrete per-copy handedness allocations across
runs. It does not change Sparrow or Jagua. The obstacle constructor compares
both permitted handedness choices for each placement. Every result still has
to pass the independent validator.

Tilt samples come from `rules::allowed_rotations` for each piece and mirror
state. Sparrow uses zero, +/-min(tilt, 0.5 degrees), and both endpoints per base
angle. The obstacle path uses the base and endpoints. A zero piece override
removes inherited fabric tilt. Non-finite or out-of-range overrides are rejected.

Nest and match now derive bundle numbers from `rules::bundle_sizes`. This
includes numeric sizes in numeric order. Without an order, the shared contract
has one garment; the old nest-only rule that invented separate garments for
separate size labels is removed. A no-order job must use one size label;
multiple sizes need an explicit order, matching the validator's one-size-per-garment rule. This is checked before starting a search.

For a slot that can use a fold half, the constructor now compares the half on
the fold edge with a full piece on two layers at each placement. The first
construction still places fold candidates first. Later constructions vary
piece order. Extra layer copies remain explicit surplus warnings. Fold benchmark
summaries include demand efficiency as well as occupied-outline efficiency:
surplus pieces must not inflate a quality claim. This change does not make a
single placement supply two different garment bundle IDs. That needs a shared
contract if the two layers are to belong to separate garments.

`nest_with_tuning(job, options, tuning)` exposes compression share, sampler
counts, exploration shrink, solution-pool spread, initial enumeration, and
portfolio scheduling without changing `NestOptions`. Existing callers retain
the 80/20 split until development evidence supports a replacement. Sequential
restarts and race-then-focus keep the full requested worker pool, retain a valid
incumbent, and share the total wall-clock allowance. Race-then-focus uses 30%
for probes and the remaining time to refine their best result. Setup and checks
can still exceed a nominal search allowance.

The experiment protocol and named configurations are in
[`bench/experiments/v03`](../../bench/experiments/v03/README.md). They are
hypotheses until measured. The 40 development IDs are disjoint from the 300
confirmation IDs and the 60 matched-duration IDs. The converter keeps the old
confirmation IDs unchanged while updating each task's supported rules.

Pending validator errors are never returned as valid markers. The adapter can
label a rejection `pending_validator` only after its own geometry/count checks
pass, the original validator errors are limited to the old per-piece contract,
and an explicitly relaxed diagnostic job validates. The diagnostic never enters
progress callbacks or scores. Final confirmation must use the integrated new
validator, with no pending tasks.

No new dependencies are needed. Sparrow remains MIT and Jagua its existing
MPL-2.0 dependency. No engine source is copied, vendored, or patched.
