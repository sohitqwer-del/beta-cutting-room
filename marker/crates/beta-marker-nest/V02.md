# Nesting engine 0.2

The launch update replaces the unbounded obstacle constructor with bounded
construction and incremental compaction. See [LAUNCH_FIX.md](LAUNCH_FIX.md) for
the current deadline and cancellation contract, regression tests and measurements.

The public entry points remain `nest` and `nest_with_progress`. Every returned
result passes the independent core validator. The adapter also checks the new
rules itself. No engine source is patched and no dependency is added.

## Fixed pieces and defects

Jagua 1.0.0's `spp::Strip` stores only height, width and shape-modification
settings. Its conversion to a container creates an empty hole list. Sparrow
0.3.0's separator builds workers for every placed item. A warm-start item is
therefore movable; importing a fixed piece as a warm-start item does not lock it.

Jobs with fixed pieces or defects use the adapter's obstacle-aware multistart
packer. It checks full f64 polygons, tries allowed rotations and width positions,
slides outlines towards polygon contact, and varies the construction order.
The first construction puts fold halves first. Later searches mix shuffled
orders with fold-first orders, and compact a complete checked incumbent.
Fixed placements stay outside that search. Their outlines count towards demand
and the minimum marker length. Empty space before and between fixed pieces
remains available. Defects have no piece clearance; only their interior is
excluded. Invalid fixed geometry, duplicate identities and excess demand return
errors. The adapter does not move a locked piece to repair an invalid layout.

This is an adapter construction/compaction heuristic, not Sparrow's separator.
It can produce less dense markers, especially with many obstacles. It uses
sampled boundary positions and does not prove that no better placement exists.

## Portfolio and warm start

`runs` selects independent seeded searches. Seeds after the first use a wrapping
64-bit increment. Runs share the requested wall-clock search interval. When the
run count exceeds concurrency, each wave receives an equal part of that interval.
Separator worker pools and run coordinators are included when dividing the
available CPU count. Both phase pools are counted: Sparrow retains the exploration
pool while it creates the compression pool. On hosts with fewer than three
logical CPUs, the adapter packer avoids those extra pools. Startup and final
checks add overhead, as in version 0.1.
The best independently valid result wins; a failed run cannot replace it.

For ordinary jobs, a previous result is mapped through Jagua's original-shape
coordinate system, imported with `spp::io::import_solution`, and passed to
Sparrow's `optimize(..., Some(&solution))`. The previous valid result also remains
an incumbent, so warm-starting cannot increase the returned length. On the
obstacle path it is an incumbent while fresh constructions seek improvements.
The obstacle path checks its deadline inside expensive placement loops and
retains the best complete checked result when it expires. The optional
`nest_with_cancellation` entry point adds an atomic cancellation flag and uses
this bounded path for all jobs. Preparation and final validation add overhead.
Warm starts must fit the current job, its width, demand and rules. They do not
lock pieces; use `fixed` for that.

## Garments, directions and reflections

Every placement receives a garment bundle. Standard apparel sizes use
XXXS, XXS, XS, S, M, L, XL, XXL, 3XL, 4XL, 5XL order; other size labels follow
lexical order. Thus S1 M2 creates bundles 0, 1 and 2. Without an order, there is
one garment per distinct size; unsized pieces form their own garment. Each
garment's piece quantities stay together.

For `one_way_per_bundle`, an entire bundle receives direction 0 or 180 degrees
relative to grain. Runs try all-forward and alternating assignments. A piece
whose rotation rule forbids reversal forces that bundle forward. A fixed piece
sets its bundle's direction. Directions do not change within a Sparrow run.

Faceless open fabric uses five normal/mirrored allocations across runs:
original demand, its inverse, alternating copies/bundles, all normal, all
mirrored. Each physical copy is an engine item, and total demand stays constant.
This searches useful allocations without requiring Sparrow to change an item's
reflection state. It does not search all 2^N possible assignments. With one run,
the original allocation is retained. The obstacle path also varies allocations
between construction attempts.

## Layers, folds, blocks and shrinkage

Folded/tubular demand is calculated per garment. A full placement cuts one normal
and one mirrored copy. Remaining normal copies with a fold line use half outlines
on a fold edge; a remaining copy without a fold line cuts two layers and reports
the surplus. On-fold halves use `rules::placed_outline`. The transformed fold
line lies exactly on y = width, or y = 0 for a tubular lower fold. Fabric edge
clearance does not apply on a fold edge. The marker start still has clearance.
Efficiency uses the physical area occupied on the spread, as core metrics do;
it is not doubled for the second layer.

These are initial demand slots, not mandatory half placements. The packer also
tries a full two-layer cut for each suggested half and compacts the result. Full
cuts can add surplus copies. The launch benchmark therefore also reports useful
demand yield, which excludes surplus area. Folded full cuts requesting a normal
and mirrored pair can use either primary hand without enabling optional flipping
for single-layer fabric.

Fusing blocks use a rectangle around the outline in its grain-aligned frame,
expanded by `block_margin`, then mapped back into piece coordinates. That
rectangle rotates and mirrors with the placement. Piece IDs remain unchanged.
The result warnings list blocked pieces.

Useful outline area is used for efficiency; block waste is excluded. On layered
faceless fabric, pooled demand uses one full placement per two copies. An odd
copy uses a fold half when possible, otherwise one surplus layer is reported.
A positive fusing margin uses a full two-layer block rather than a fold half,
because a margin around that half would cross the physical fold edge.

Shrinkage is applied once through `rules::effective_job` before creating engine
geometry, checking fixed placements or importing a warm start. The result warning
states that transforms refer to the effective job. The final independent check
receives the original job, so its shrinkage-aware validator can apply the same
conversion.

## CLI and evidence

```text
beta-marker nest job.json --time 60 --runs 5 -o result.json
beta-marker nest job.json --fixed edited-result.json -o renest.json
beta-marker nest job.json --warm-start previous-result.json -o improved.json
```

`--fixed` reads only placements with `locked: true`. The library's `fixed` list
keeps every supplied placement, whether or not its `locked` flag is set.

`feature_bench` writes the variant job, effective job, options, result, independent
validation, progress and summary into its output directory. It supports baseline,
fixed, warm, defects, bundles, faceless, folded, tubular, blocks and shrinkage.
The fold conversion is explicitly for the open FreeSewing Teagan fixture: full
front/back receive their symmetry line at local x = 0; sleeves remain pairs.
Source datasets are never changed.

## Verification and integration

`cargo test --workspace` passed after qa2 integration: 108 passed, two
existing long tests ignored. The 31 nesting unit tests took 7.85 s; the synthetic
garment integration test took 2.29 s. Clippy with `-D warnings` passed without
warnings. Independent validation also gates progress candidates before they
can become the best result or trigger a callback. New search tests use 0.05 s budgets and at
most two separator workers. The thread-budget test checks 1–64 logical CPUs and
1–70 runs, including both retained engine pools.

The branch merges qa2 commit `d4c6a82` after checking its recorded passing
workspace tests (89 passed, two ignored) and zero-warning Clippy report. Layer,
block, shrinkage and bundle tests now exercise the public entry point and its
independent gate. Faceless allocation tests also check a specified mirror split
directly, then validate that result independently. Combined fixed/matching/shade
cases still need re-testing with the matching agent's branch.

For integration, the core owners should share the natural garment-size bundle
order above. The adapter reuses qa2's public `validate::cut_outline` for physical
cut boundaries and keeps its own polygon, spacing, demand and fold checks. As qa2
requests, move that helper to shared rules/geometry and use it for block-aware
length in `compute_metrics`, while keeping useful outline area for efficiency.
No model fields need to change.

```text
cargo run --release -p beta-marker-nest --example feature_bench -- <job.json> 60 <out> baseline 3
cargo run --release -p beta-marker-nest --example feature_bench -- <teagan.job.json> 60 <out> tubular
```

Set the assigned `CARGO_TARGET_DIR`, `CARGO_BUILD_JOBS=3` and `BETA_DATA_DIR` before
Cargo commands. Long measurements belong outside the repository.
